## Automation Command Payload

`POST /command` accepts the Core automation runtime contract:

```json
{
  "contract_version": "automation.runtime.command.v1",
  "command": "refresh",
  "target": {
    "config_id": "home-firewall",
    "device_id": "home-firewall",
    "entity_id": null
  },
  "params": {},
  "capability": "device.refresh",
  "capability_requirements": ["device.refresh"]
}
```

Return `{"ok": true, ...}` for accepted commands. For validation failures, return `{"ok": false, "error": "unsupported_capability", "message": "..."}` with an appropriate 4xx status.

## Recommended Endpoints

Keep `manifest.json`, the contract source file, and route handlers in sync.

`refresh` triggers a new status poll and does not change firewall state.
`diagnostic_ping`, `restart_service`, `start_service`, and `wake_on_lan` are
disabled by default and accept only targets explicitly allow-listed in the
active firewall configuration. The runtime does not provide arbitrary API,
shell, or firewall-configuration actions.

The runtime emits `network.gateway.online/offline`,
`network.interface.up/down`, and `network.service.recovered/stopped` only after
an observed child state transition; the initial snapshot does not create alerts.

Optional client inventory merges DHCP and ARP observations into child entities.
Log events are content-hash deduplicated after a silent initial baseline.
Certificate alerts fire as a certificate crosses 30, 14, 7, 1, and 0 days.
CARP virtual IP child entities report primary/backup role transitions.
